# Вся Мысль на своём сервере

Сайт, база данных, картинки, «живые» доски и HTTPS на одной машине с Ubuntu (например, на VPS в России). Эта установка заменяет `deploy/realtime`: она занимает те же порты 80 и 443 и при первом запуске сама останавливает прежний сервер досок.

## Что нужно заранее

- Домен, у которого запись **A** указывает на IP сервера. Установщик это проверяет.
- Почта для писем со ссылкой входа: строка `SMTP_URL` от почтового сервиса, например `smtps://логин:пароль@smtp.example.ru:465`, и отправитель на вашем домене. Без неё сайт работает, но войти по почте нельзя.

## Установка и обновление

```bash
curl -fsSL https://raw.githubusercontent.com/lopsserg02-collab/mysl/main/deploy/server/install.sh | sudo bash
```

Первый запуск спрашивает домен и почту, сам придумывает пароли и сохраняет всё в `/opt/mysl/deploy/server/.env`. Следующие запуски только обновляют код и перезапускают сервисы.

Почту можно добавить позже: впишите `SMTP_URL` и `EMAIL_FROM` в `.env` и выполните `docker compose up -d` в `/opt/mysl/deploy/server`.

## Что внутри

| сервис | что делает |
| --- | --- |
| `db` | Postgres 16; данные в томе `pgdata`, наружу не открыт |
| `web` | сайт (Next.js); при каждом старте применяет новые миграции; картинки в томе `files` |
| `realtime` | совместная работа на досках, доступен по `wss://<домен>/rt` |
| `caddy` | HTTPS-сертификат и раздача по адресу домена |
| `jobs` | раз в сутки: копия базы в `/opt/mysl-backups` (хранятся 14 последних) и очистка корзины |

Картинки (том `files`) в эти копии не входят: они лежат на диске сервера. Чтобы не потерять их вместе с сервером, включите у хостинга снимки диска.

Восстановить базу из копии: `gunzip -c /opt/mysl-backups/mysl-ДАТА.sql.gz | docker compose exec -T db psql -U postgres mysl` (в пустую базу).
