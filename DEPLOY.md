# Тестовый стенд Мысли

Сайт работает на Vercel, сервер совместной работы на Render, база и вход в Supabase. Все три сервиса бесплатные. Аккаунты и ключи создаёте вы; ключи вставляются только в панели этих сервисов, никуда больше.

Стенд собирается из ветки `main`, поэтому сначала влейте PR со всеми изменениями (ссылка в чате).

## 1. Supabase: данные для подключения

В панели проекта Supabase запишите себе:

- **Project Settings → API:** Project URL, ключ `anon` (или publishable) и ключ `service_role`. Последний секретный: он нужен только сайту и не показывается в браузере.
- **Connect** (кнопка вверху) **→ Connection string → URI:**
  - строка **Transaction pooler** (порт 6543) нужна для Vercel;
  - строка **Session pooler** (порт 5432) нужна для Render.
  
  В обе подставьте пароль базы вместо `[YOUR-PASSWORD]`.

Таблицы, права доступа и хранилище картинок нужно создать до запуска стенда. Если миграции не применились автоматически, откройте в Supabase **SQL Editor**, вставьте целиком файл `db/supabase-setup.sql` из репозитория и нажмите **Run**. Делать это нужно один раз.

## 2. Общий секрет

Придумайте длинную случайную строку, хотя бы 32 символа (подойдёт генератор паролей). Это `REALTIME_SECRET`. Одна и та же строка понадобится и на Render, и на Vercel.

## 3. Render: сервер совместной работы

1. Зарегистрируйтесь на render.com через GitHub.
2. Нажмите **New → Blueprint** и выберите репозиторий `mysl`. Render прочитает файл `render.yaml`.
3. Заполните `DATABASE_URL` (строка Session pooler) и `REALTIME_SECRET`, затем нажмите **Apply**.
4. Когда сервис запустится, скопируйте его адрес, например `https://mysl-realtime.onrender.com`. Для сайта замените в нём `https` на `wss`: получится `wss://mysl-realtime.onrender.com`.

Бесплатный сервер засыпает, если им 15 минут никто не пользуется. Первое открытие доски после паузы может «подключаться» до минуты. Это нормально.

## 4. Vercel: сайт

1. Зарегистрируйтесь на vercel.com через GitHub.
2. Нажмите **Add New → Project** и импортируйте `mysl`.
3. В **Environment Variables** добавьте:

| Имя | Значение |
| --- | --- |
| `DATA_LAYER` | `postgres` |
| `DATABASE_URL` | строка Transaction pooler |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ключ anon / publishable |
| `SUPABASE_SERVICE_ROLE_KEY` | ключ service_role |
| `REALTIME_SECRET` | строка из шага 2 |
| `NEXT_PUBLIC_REALTIME_URL` | `wss://…` из шага 3 |
| `NEXT_PUBLIC_SITE_URL` | адрес сайта, например `https://mysl.vercel.app` (ссылки в письмах) |
| `CRON_SECRET` | ещё одна длинная случайная строка: ею защищена ежедневная очистка корзины |
| `RESEND_API_KEY` | ключ из resend.com → API Keys (необязательно: без него письма не отправляются) |
| `EMAIL_FROM` | отправитель на домене, подтверждённом в Resend, например `Мысль <hello@ваш-домен>` |

4. Нажмите **Deploy** и скопируйте адрес сайта, например `https://mysl.vercel.app`.

## 5. Supabase: куда возвращать после входа

В **Authentication → URL Configuration** укажите:
- **Site URL:** адрес сайта;
- **Redirect URLs:** добавьте `https://<адрес сайта>/auth/callback`.

Вход через Google заработает, когда вы включите его в **Authentication → Providers → Google**. Без этого работает вход по ссылке на почту.

## 6. Проверка

Откройте сайт, введите почту и нажмите на ссылку из письма. Создайте доску и откройте её во второй вкладке или на телефоне: стикеры должны появляться в обеих сразу.

Письма о приглашениях на доску и упоминаниях отправляет Resend. Пока `RESEND_API_KEY` не задан, они просто не уходят, остальное работает. Уведомления внутри Мысли (колокольчик) работают и без почты.

Доски из корзины удаляются насовсем через 30 дней. Это делает ежедневная задача Vercel Cron из `vercel.json`; ей нужен `CRON_SECRET`.

Перед запуском этой версии выполните в Supabase **SQL Editor** файл `db/migrations/0006_notifications.sql` (если базу создавали из `db/supabase-setup.sql` до его появления).

Встроенная почта Supabase отправляет лишь несколько писем в час. Для теста этого хватит, для настоящих пользователей подключим свою почту (Resend).
